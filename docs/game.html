把一场在线
做成一颗不丢账的心

cmd/game 是 gforgame 的逻辑服务器——承载全部业务与玩家数据：先入内存缓存、再异步落库，靠 Actor 串行化每个玩家，优雅关服时冲刷到底。

01

角色与定位

进程：cmd/game，独立可执行程序，是业务主入口，承载全部业务逻辑、玩家数据、排行榜、公会、背包、邮件等模块。

  • 对外（直连模式）：WebSocket 服务，监听地址为 ServerUrl（见「配置」）。
  • 对外（网关模式）：作为逻辑服节点，与 cmd/gate 各维持一条长连接，不直接对客户端；由 useGateMode 决定。
  • 对内：MySQL 持久化 + 进程内缓存 + Actor 并发模型。
  • 所有业务逻辑、数据读写在逻辑服完成；网关只做转发。
02

启动与运行

# 编译（部署）
make game            # 本机编译 → bin/game
make build-linux     # 交叉编译 linux/amd64

# 运行
go run ./cmd/game    # 源码直接跑（需先配好 config-game.yml 的 MySQL）

配置：config/config-game.yml（逻辑服配置）+ 全局 config/default.yml（servers 节点表），经 ServerConfig 读取。

关键配置：db.url（MySQL DSN）、server.url（WS 监听地址）、server.useGateMode（是否网关模式）、http.url（管理 HTTP）、pprof.addr（性能监控）。

2.1 · 启动流程与数据恢复 main.go

启动顺序即「数据恢复」的顺序：加载配置 → 建库表 → 载入业务配置 → 预热玩家资料索引 → 启动定时任务 → 启动网络。

  1. 1读配置：config.Load() 载入 config-game.yml 与 default.yml。
  2. 2初始化 DB：persistence.InitMysql() 用 GORM + DSN 打开全局单例 persistence.Db（慢查询阈值 1s）。
  3. 3建表 DDL：bootstrap.InitMysqlDdl() 对 PlayerPO / FriendPO / SystemParameterEnt 依次 AutoMigrate。
  4. 4载入业务配置：config.InitConfig() 加载 Excel 静态数据（item / hero / mail 等）。
  5. 5装配服务：bootstrap.InitServices() 用 dig 装配全部 Service / Repository / 基础服务，并对实现 ServiceModule.Init() 的模块统一初始化。
  6. 6预热 + 任务恢复：
    • InitBusiness() → PlayerProfile.LoadPlayerProfiles() 从 DB SELECT id,name,... 重建 id→profile 与 id↔name 内存索引（启动即恢复，不逐账号拉全量），并 ScheduleAllActivity()。
    • StartSchedulers() → System.StartSystemTask() 启动每日/每周/每月重置、开服等 cron 任务。
  7. 7注册路由：NewMessageRoute() + 各 route 模块 RegisterMessageHandlers。
  8. 8构建派发链：NewGameTaskHandler(router, actorSystem) + 共享匿名 Actor；网关模式再插 NewGateTransformHandler()。
  9. 9启动 WS：ws.NewServer(...).Start()，随后启后台管理 HTTP 与 pprof。
  10. 10阻塞等待退出：捕获 os.Interrupt / SIGTERM，或 node.RunningChan()（/api/stop）。
  11. 11优雅停服：node.Stop() 停监听与连接 → s.DbService.Shutdown() 冲刷所有未落库缓存（见 §8）。
启动/数据恢复             停服冲刷
 InitMysql ───► AutoMigrate ───► InitConfig ───► InitServices(dig)
    ───► InitBusiness(索引恢复) ───► StartSchedulers(定时任务)
    ───► 注册路由 ───► ws.Start ───► 阻塞等待信号
 SIGTERM / /api/stop ──► node.Stop() ──► DbService.Shutdown()
03

网络接入：解包 / 心跳 / 断线

3.1 · WebSocket 服务 ws/server.go

ws.NewServer 在 server.url 上用 net/http + gorilla/websocket 升级连接，每个连接 newWSConn 后 go dispatch.CreateServeSession(...)。

CreateServeSession 流程

  1. 1创建 BaseSession（session.NewSessionWithProtocol）：双通道 dataToSend/DataReceived，私有协议栈 BinaryProtocolAdapter，默认 PayloadModeDecode。
  2. 2触发 OnSessionCreated → go session.Read() + go session.Write() 双协程。
  3. 3阻塞在 eventLoop，会话结束才 OnSessionClosed 并 conn.Close()。

3.2 · 读循环 / 解包 session/io.go · protocol/protocol.go

  • WebSocket 走 readWebSocketStream：阻塞读一整帧，首帧决定协议类型（文本→JSON，默认二进制），MarkReadActivity() 维护最后活跃时间。
  • 二进制解包（Protocol.Decode）：固定 12 字节头 [Size|Index|Cmd] + 消息体；逐帧校验 Size ≤ 64KB、取足 body，产出多个 Packet，按 Cmd 反射出 *protos.ReqXxx，用 MessageCodec.Decode 解码成 RequestDataFrame 投进 DataReceived。
  • 写循环（Write()）：从 dataToSend 出队写入 net.Conn，出错即关。

3.3 · 心跳与空闲超时 dispatch.go

  • 心跳：客户端定时发 HeartBeat（正常路由，仅刷新 lastRecvUnixNano）。
  • eventLoop 的 idleCheckTicker（每 1 分钟）读 LastReadAt()，超过 DefaultSessionIdleTimeout（10 分钟）判心跳超时，日志后主动 session.Close()。

3.4 · 断线 / 顶号 / 重连 registry.go · online_playerer_registry.go

  • 主动顶号：重复登录时（见 §5）注册表发现旧 session，发 SendAndClose(PushReplacingLogin{}) 顶掉。
  • 断线（session 层）：OnSessionClosed 解绑 playerId，session.Unbind 清理 ownerId↔sid；客户端重连需重新登录（纯状态在内存）。
  • 网关模式：解绑在线玩家，等网关重连后重建 gateSession。
04

路由分发与消息处理 （核心）

4.1 · 会话级消息链 IoDispatch network/dispatch

每封 DataReceived 帧经 eventLoop → OnMessageReceived → BaseIoDispatch.Pipeline（有序链）逐段执行，任一返回 false 终止本帧：

pipeline = [ GateTransformHandler(仅网关模式) → GameMessageHandler ]

4.2 · GateTransformHandler（网关模式）

拆解 TransferGateToLogic 外层：取出内层 Cmd/Index/PlayerId/Body，用 json 解码出真正的 ReqXxx，回填 frame.Header 后放行；非转运消息直接放行。

4.3 · GameDispatch（cmd/game/dispatch.go）

  1. 1补齐 playerId：fillPayloadFromSession 从 session 的 ownerId 取。
  2. 2取 handler：router.GetHandler(cmd) 查 network.Handler。
  3. 3参数校验：带 NeedValidate 则 ValidateStruct，失败回 I18N_COMMON_PROTOCOL_VALIDATION_FAILED 并终止。
  4. 4打印日志：logInboundMessage（忽略心跳）。
  5. 5Actor 串行投递：
    • 登录消息（CmdReqPlayerLogin）→ 共享 SharedAnonymousActor。
    • 其它 → game/player/<playerId> 的玩家 Actor（GetOrCreate，懒创建）。保证同一玩家消息单协程串行。
    • 邮箱满 / 关闭则丢弃该帧。
  6. 6dispatchMessage：callGeneratedRouteHandler 静态派发（route_dispatch_gen.go）首选，缺失则反射兜底；带 panic 回收与错误回包。
  7. 7回包：直连 session.Send；网关模式走 io.NotifyByPlayerId。

4.4 · 静态路由（约定 > 配置）

network/handler.go 扫描导出方法签名自动登记：(receiver, [playerId], [session], [index], reqIndex 尾参为 Ptr) 即为 handler；Cmd 与 Handler 存 Handlers map[int32]*Handler。方法名 ReqXxx 与返回 ResXxx 由代码生成器关联。改动协议/签名后必须 go generate ./cmd/game，保持 register_gen.go 与 route_dispatch_gen.go 一致。

4.5 · 推送通道 internal/io/notify

  • NotifyByPlayerID(playerID, index, resp)：直连 → session.Send；网关模式 → 封装 TransferGateToServer 经 gateSession 发回网关。
05

登录认证（DoLogin）

ReqPlayerLogin ──► PlayerRoute.ReqLogin ──► PlayerService.DoLogin
  1. 1校验 msg.PlayerId 非空；newCreated = 资料索引中不存在。
  2. 2GetOrCreatePlayer：Repo.GetPlayer（命中内存/DB 恢复），无则新建并 SavePlayer。
  3. 3顶号（直连模式）：注册表找旧 session → SendAndClose(PushReplacingLogin)；网关模式转到网关端判断。
  4. 4绑定：s.SetOwnerId(id) + session.Bind(sid, id)，AddOnlinePlayer 登记在线。
  5. 5异步 goroutine：每日/每周重置检测（补离线段）、发布 PlayerLogin、PushLoadComplete。
  6. 6返回 ResPlayerLogin（id / level / name 等）。
身份绑定落在 session.Bind（ownerId↔sid 双向映射）与 OnlinePlayerRegistry。登录之后 frame.Header.Payload 即为 playerId，路由与推送都依赖它。
06

缓存与 MySQL 持久化

6.1 · 缓存层 cache + 资料索引

  • 进程内缓存 manager.go：30 分钟过期、10 秒清理，未命中回源 loader。
  • 玩家资料索引 PlayerProfileService：启动预载全部摘要，供列表 / 好友 / 匹配。
  • 玩家聚合缓存 PlayerRepository.GetPlayer：内存优先，未命中 GetPlayerByID 回源并缓存；SavePlayer 写缓存 + AsyncDBService.SaveToDb。
  • OnlinePlayerRegistry：playerId→session 与在线集合（心跳 / 推送 / 每日重置遍历）。

6.2 · 回写链路（异步持久化） persist 包

业务改玩家 → 事件总线(PlayerAttr/EntityChange) → SavePlayer
   → PlayerPO 快照 → AsyncDBService.SaveToDb → EntitySavingStrategy → Db.Save/Delete

AsyncDBService 分工：

  • playerWorker：PersistContainerGroup（NumCPU() 个延时容器分片，同 id 哈希落同片保序），对同一玩家 3 秒内合并为一份最新快照，到期才落一次；落库期间再被更新会重新调度，保最终一致。
  • commonWorker：QueueContainer，逐条串行，适合非玩家实体。
  • EntitySavingStrategy.DoSave：IsDeleted() → Db.Delete；否则 Db.Save（upsert）。
  • 失败自动重试 + 5 分钟一次错误日志降噪。

6.3 · 优雅冲刷（Shutdown）

node.Stop() 先停收新连接
  └─ AsyncDBService.Shutdown()
       playerWorker.ShutdownGraceful()  // DelayContainer
       commonWorker.ShutdownGraceful()   // QueueContainer
  • DelayContainer.ShutdownGraceful：running=false → wg.Wait() 等已调度任务 → Range 把 pending 中剩余最新快照全部 DoSave 落库，再补一次兜底。
  • QueueContainer 同理：close(queue) → wg.Wait → Range 剩余落库。
因此关服不丢账——无论是否到达延时窗口，全部已变更数据都会落库。

6.4 · 启动数据恢复（与停服对应）

  • 玩家档案：登录即按需 repo.GetPlayer(id) 从 DB 读出并缓存；全量索引启动时一条 SELECT 摘要建好。
  • 系统时间线（每日 / 每周 / 每月重置、开服）：System.StartSystemTask() 从 SystemParameterEnt 载入断点，定时驱动，跨服重启重置不重。
  • 业务配置 config.InitConfig() 一次性载入进程内存。
07

定时任务与 Actor

7.1 · Actor 并发 actor 包

  • ActorSystem.Spawn / GetOrCreate：每玩家一个 ActorRef（邮箱 256），Tell 投递，runActorLoop 单协程串行消费（CSP）；handleMessageSafely 兜住条消息 panic。保险 ActorRef.Task(fn) 供离线重置等。
  • 系统级：SharedAnonymousActor 处理登录等匿名消息；PlayerTaskDispatcher.DispatchPlayerTask 按 playerId 往玩家串行队列塞任务。

7.2 · 定时任务 schedule + system

  • 表注册 cron/表达式：Schedule(task, delayMs)（DefaultTaskScheduler，支持取消）。
  • 系统服务：开服、每日 / 每周 / 每月重置——读取 SystemParameterEnt 断点，重置时广播全部在线玩家并补离线段；活动 ScheduleAllActivity 也走这套。
08

优雅停服完整时序

  1. 1收到 SIGTERM / os.Interrupt / /api/stop，入口 break 出阻塞。
  2. 2node.Stop()：http.Server.Shutdown(3s) 停收新 WS、listener.Close()，并触 OnSessionClosed 逐个解绑在线玩家（不再进新业务）。
  3. 3s.DbService.Shutdown()：冲刷所有待落库数据（见 6.3）。
  4. 4打印 game server is closed，进程结束。
停服不再接纳新玩家 / task；关闭期间变更照常进入 AsyncDBService（stop 后入列即被 ShutdownGraceful 立即冲刷）——不丢账。
