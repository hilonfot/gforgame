让消息
穿过一台中转机

cmd/gate 是 gforgame 的网关进程——客户端不直连逻辑服，而是先把流量交给网关，由它负责转发、鉴权与在线管理，让故障与扩容对客户端透明。

01

角色与定位

进程：cmd/gate，独立可执行程序，作为客户端与逻辑服之间的桥梁，承载协议中转。

  • 对外（面向客户端）：WebSocket 服务，承担登录鉴权与消息转发，监听地址为 ServerUrl（见「配置」）。
  • 对内（面向逻辑服）：以 WebSocket 客户端身份，对每个逻辑服节点各维持一条连接（单连接模型）。
  • 网关只做转发与在线管理，不做业务逻辑——对客户端完全透明。
02

启动与运行

# 编译（部署）
make gate            # 本机编译 → bin/gate
make build-linux     # 交叉编译 linux/amd64

# 运行
make run-gate        # 等价于 ENV=gate ./bin/gate
go run ./cmd/gate    # 或源码直接跑

环境变量 ENV 决定加载哪份配置：ENV=gate → 读取 config/config-gate.yml，并叠加全局 config/default.yml（servers 节点表）。

节点归属：config-gate.yml 只写 server.id；该 id 会在 default.yml 的 servers 中定位节点，节点的 addr 即网关对外监听的 WebSocket 地址。

仓库默认：server.id=10001 → type:0 节点 → 网关监听 0.0.0.0:8010。

2.1 · 启动流程 main.go

  1. 1读配置：ServerConfig 载入 config-gate.yml 与 default.yml。
  2. 2服务发现初始化（按 discovery.onlylocal）：
    • true（默认）→ 按本地配置同步一次，每 5 分钟再收敛。
    • false → HTTP 拉取列表并同步，每 5 分钟刷新。
  3. 3后台协程：startBackendSessionMonitor()（每 3s 巡检）+ startOutboundDispatcher()（出站队列）。
  4. 4构建网络层：NewMessageRoute() 与在线玩家注册表。
  5. 5两个派发器：客户端侧 ClientRouter（登录 / 转发）× 逻辑侧 LogicRouter（下行 / 上线上报）。
  6. 6启动 WebSocket：ws.NewServer(...)（裸 body 载荷）。
  7. 7阻塞等待退出信号（os.Interrupt / SIGTERM）。
  8. 8优雅关服：停发现、巡检、出站队列，并关闭所有后端连接。
03

消息流转

3.1 · 客户端 → 网关 → 逻辑服（上行）

客户端
 └─ ws 消息 → ClientRouter.MessageReceived(session, frame)
     ├─ cmd == LoginCmd()（ReqPlayerLogin）
     │     └─ HandleLoginReq: 校验 → 顶号 → 绑定 → 在线注册 → transferMsgToLogic
     └─ 其它 cmd
           └─ transferMsgToLogic: 解析目标 serverID, 转发到后端
                 ├─ 确定 serverID : 登录自带 / resolvePlayerServerID 映射
                 ├─ NewTransferMessage(playerId, cmd, index, body)
                 └─ enqueueTransfer(serverID, transfer, index) → 出站队列

3.2 · 登录处理 HandleLoginReq

  1. 1解码 ReqPlayerLogin，取 playerId 与 serverId。
  2. 2校验非空，且 isBackendServerConfigured(serverId) 为真。
  3. 3顶号：若该键已在线，给旧连接发 ReplacingLoginPush 后关闭。
  4. 4绑定 sessionPlayerKey = <serverId>_<playerId>，写入在线注册表与全局会话表。
  5. 5记录 playerId → serverId 映射（playerServerIDMap）。
  6. 6将登录请求作为普通转发消息发给目标逻辑服。

3.3 · 逻辑服 → 网关 → 客户端（下行）

后端 session → consumeBackendSession → logicIoDispatcher.OnMessageReceived
  └─ LogicRouter.MessageReceived
      ├─ cmd == TransferCmd()（TransferGateToLogic）
      │     └─ forwardTransferToClient:
      │           ├─ 取 playerId / cmd / index / body
      │           ├─ resolveBackendServerID(会话) → serverID
      │           ├─ 以 serverId_playerId 定位客户端 session
      │           └─ 用客户端 codec 重编码 → session.SendRaw 原样发回
      └─ 其它非法/未知 → 忽略

3.4 · 下线

OnSessionClosed 触发（仅当自己确实是该玩家的当前会话，规避顶号竞态）：

  • 确认 sessionPlayerKey 仍为当前绑定 → notifyLogicPlayerLogout 通知后端清理在线状态，unbindPlayerServer 删除映射。
  • 从在线注册表 RemoveOnlinePlayer。
04

后端连接池与重连

backendPools 以 serverID 为键，每个逻辑服节点只维持一条连接。

  • 收敛 reconcileBackendPools(desired)：新增 → 拨号；地址变化 → 关旧连新；消失 → 关闭并清理。
  • 拨号 connectBackendSession：成功后先替换、再关旧连接（避免空窗），随后触发 notifyOutboundDispatcher。
  • 消费 consumeBackendSession：常驻监听 DieChan()（断开）与 DataReceivedChan()（下行帧）。
  • 重连 scheduleReconnect：延迟 1500ms，失败则限流记日志并再次调度；已移除节点不重连。
  • 巡检 checkBackendSessions：每 3s 巡检，发现死连接即清理并调度重连。
05

出站队列（缓冲与容错）

outboundQueue（容量 4096）+ LimitedList（上限 4096），逐个 sendTransferToBackend 推向后端：

  • 后端不可用 → 保留在 pending，等重连或 notify 后补发。
  • 超出上限 → 丢弃最旧一条并记日志，防止无限堆积。
  • enqueueTransfer 在队列满时阻塞写，保证消息不丢。
与 README 一致：“服务器故障时网关缓存消息、恢复后补发”——客户端无需重连即可继续通信。
06

协议适配与跨语言

协议通过 gateway/contract 接口解耦：

接口作用
ClientLoginAdapter登录协议最小契约：LoginCmd / 解码 / 顶号推送
TransferCodec转发包契约：TransferCmd / 构造 / 解析

当前实现 internal/gatewayadapter/proto_gate_adapter.go：

  • LoginCmd() = protos.CmdReqPlayerLogin
  • TransferCmd() = protos.CmdTransferMsgGateToLogic
  • 转发包 TransferGateToLogic{ PlayerId, Cmd, Index, Body []byte }，顶号推送 PushReplacingLogin

若后端为其它语言（如 Java 版 jforgame），只需新写一套实现 contract 的 adapter 并对齐协议，其余转移、队列、重连均不变。

07

配置

网关使用 config/config-gate.yml + config/default.yml（可选 config-<env>.yml）。

config-gate.yml（仅自身标识）

server:
  id: 10001        # 网关节点 ID

default.yml 的 servers 是节点总表，用 useGateMode 与 type 区分角色：

servers:
  - id: 10001         # 网关自身节点（type:0）
    type: 0
    useGateMode: true
    addr: 0.0.0.0:8010   # 网关对外 WebSocket（ServerUrl）
    httpAddr: 0.0.0.0:8090
  - id: 1001
    type: 1           # 逻辑服（logicServerType = 1）
    useGateMode: true
    addr: 127.0.0.1:8011   # 网关后端连接地址
    httpAddr: 0.0.0.0:8091

服务发现（可选 Extra）：

discovery:
  onlylocal: false        # false=HTTP 动态发现；缺省/true=本地配置
  apiurl: http://admin/discover/server/list   # 动态发现接口

server_discovery.go 用 HTTP GET 拉取服务器列表，过滤 id==0、缺 ip、useGate==0 的行，转成 DynamicServerNode 后经 SyncDynamicServers 全量同步并按 reconcileBackendPools 收敛连接。每 5 分钟刷新一次。

08

常见配置动作

场景做法
新增逻辑服节点在 servers 加 type:1 条目，或由动态发现推送；网关下轮收敛自动连上
移除后端节点从配置或发现列表移除；网关自动断开
网关连不上某后端自动处理：断开后 1500ms 重连，辅以每 3s 巡检，直至恢复
消息发不出去检查 isBackendServerConfigured 的服务器类型 / IP 是否有效
