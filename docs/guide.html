gforgame 是一个轻量级手游服务端框架：消息处理不写显式函数表，靠扫描方法签名；配置是 Excel；并发是「每实体一协程」的 Actor。这份手册告诉你每一步在哪个文件写什么。

01

新增消息与处理方法

核心原则：约定大于配置。路由扫描方法签名自动注册（network/handler.go 的 parseHandlerSignature），不写显式 handler 表。对应三类文件：

职责文件动作
消息定义internal/protos/<mod>.go加 Req/Res 结构体 + cmd_ref；message.go 加 Cmd 常量
业务逻辑internal/service/<mod>/…纯逻辑，不碰协议
路由薄层internal/route/<mod>.go处理方法组装请求 → service → 响应

1.1 · 三步走 step by step

  1. 1在 protos 里定义消息。每个结构体必带 _ struct{} cmd_ref:"CmdXxx"，把消息关联到 message.go 的常量；字段用 json tag 对齐客户端。
  2. 2在 route 加处理方法，签名：首参 session 或 playerId（可跟 index），末参 *ReqXxx，返回 *ResXxx，方法名 ReqXxx。Req→Res、结构体→Cmd 由生成器推导。
  3. 3在 cmd/game/main.go 的 modules 列表加 route.NewXxxRoute(...)。最后 go generate 重新生成路由。

消息结构体示例（参照 protos/friend.go）：

type ReqFriendSearchPlayers struct {
  _   struct{} `cmd_ref:"CmdFriendReqSearchPlayers"`  // 必须有
  Key string                                    `json:"key"`
}

处理方法示例（参照 route/friend.go）：

func (r *FriendRoute) ReqSearchPlayers(
    playerId string, index int32, msg *protos.ReqFriendSearchPlayers,
) *protos.ResFriendSearchPlayers {
  p := r.playerrepo.GetPlayer(playerId)
  items := r.service.SearchByKey(msg.Key)
  return &protos.ResFriendSearchPlayers{Code: 0, Items: items}
}

1.2 · 重新生成 go generate

go generate ./cmd/game      # 等价 go run ./internal/tools/gen all
  # protocolgen → 导出 TS 客户端协议 + 生成 register_gen.go
  # routedispatch → 读 register 生成 route_dispatch_gen.go
make game

不跑这步，运行期找不到 handler、或构建报错。register_gen.go / route_dispatch_gen.go 是自动生成，别手改。

02

业务配置读取（Excel）

配置不是 yml，而是 config/excel/*.xlsx，由 config.InitConfig() 一次性全量加载进内存。（系统/服务器级配置是 default.yml + config-{env}.yml，走 viper，见另文。）

新增配置表 excel → struct → loader

  1. 1新建 config/excel/xxx.xlsx：第 3 行为列头，前面两行留作说明；第 1 列写 end 结束。
  2. 2在 internal/domain/config/ 加结构体，字段用 excel tag 映射列名（忽略大小写，支持匿名嵌入）。
  3. 3在 internal/config/data_manager.go 的 tableConfigs 登记。
type PlayerLevelData struct {
  Id    int32 `json:"id"    excel:"id"`
  Level int32 `json:"level" excel:"level"`
  Cost  int32 `json:"cost"  excel:"cost"`
}
// 普通表（主键取 Id，表名=去掉 Data 后缀小写，文件=表名.xlsx）
newDefaultTableLoader[domain.PlayerLevelData](nil, nil),
// 需要索引：{"索引名":"字段名"}，逗号分隔多字段即联合索引
newDefaultTableLoader[domain.GachaData](nil, map[string]string{"pool":"Pool"}),

业务查询：

config.QueryById[domain.PlayerLevelData](id)   // 单条（按 Id）
config.QueryAll[domain.PlayerLevelData]()       // 全量
c := config.GetContainer("quest").(*container.QuestContainer)  // 容器

需要「配置后处理」（excel 表达不了的结构，如成就链表）时，写一个自定义 container 重写 AfterLoad()，改用 newContainerTableLoader[T, C]。

事件总线（模块解耦）

common/eventbus 提供全局发布 / 订阅，适合模块间解耦（玩家加载、背包变化等）。

// 发布
eventbus.Default().Publish(events.PlayerAfterLoad, player)

// 订阅（一般放模块 Init）
eventbus.Default().Subscribe(events.PlayerAfterLoad, func(data any) {
  p := data.(*playerdomain.Player)
  // …

04

Actor 并发模型

适用「一个实体要被多协程并发访问、又要串行处理」的状态机——排行榜、公会、玩家异步任务。核心思想：每实体一协程 + 邮箱串行，改动状态只能发消息，故无需锁。

类型作用
ActorSystemactor 注册表 + 生命周期（路径为键）
ActorRef对外句柄：Tell / Ask / Task / Stop
BaseActor内嵌后获得按消息类型分发
RegisterCmd[T]强类型注册处理函数

4.1 · 三种通道 mailbox

  • Tell：异步 fire-and-forget，写消息。邮箱满返回 error，不阻塞。
  • Ask：同步等回复，适合读。以 askWrap{payload, resp} 包进邮箱，两个 select 阶段共享同一个 timer，maxAskTimeout=3s 兜底。
  • Task：把 fn 包成任务投进去，在目标协程里执行。

三者在同一 channel 排队，FIFO 天然保证串行——所以你可用「栅栏」同步：ref.Ask(syncBarrier{}) 等队列清空。

4.2 · 落地示例 rank

// 容器定义 <--> 消息（ConcurrentRankContainer 门面）
type ConcurrentRankContainer struct{ ref *actor.ActorRef }
func (c *ConcurrentRankContainer) Add(key, value any) {
  _, _ = c.ref.Ask(&AddCmd{Key: key, Value: value})
}

// actor 定义 + 注册（参照 rank_actor.go）
type RankActor struct { *actor.BaseActor; ranks *treemap.Map }
func NewRankActor(...) *RankActor {
  a := &RankActor{BaseActor: actor.NewBaseActor()}
  actor.RegisterCmd(a.BaseActor, a.handleAdd)
  return a
}
func (a *RankActor) handleAdd(cmd *container.AddCmd) actor.Message { … }

// 惰性创建 + 幂等复用
ref := sys.GetOrCreate(actor.NewActorPath("game","rank",rankType),
  func() actor.Actor { return NewRankActor(rankType, cap) })

要求业务侧无感知 actor：外面只拿到 ActorRef，方法内部都 Ask。

铁律：Ask 不得嵌套——在某个 actor 的 OnMessage 里再 Ask 同一个或互相 ask 会自阻塞。跨 actor 协作用 Tell。

若只是想在某玩家维度串行执行一段逻辑，不必 spawn 整个 actor：

// dispatch/player_task_dispatcher.go
s.playerTaskDispatcher.DispatchPlayerTask(friendId, func() {
  list := s.service.QueryMyFriendVos(p.Id)  // 在这玩家队列串行执行
})
05

Cache 模块

两层：内存缓存（读多写少、自动回源）+ 持久层（GORM 落库）。用法一在 cache/（CacheManager + Cache）：

// Init / 构造 里注册回源（miss 时从 db 加载）
r.cacheManager.Register("player", func(key string) (any, error) {
  player := r.inner.GetPlayerByID(key)
  eventbus.Default().Publish(events.PlayerAfterLoad, player)
  return player, nil
})

// 业务读写
cache, _ := r.cacheManager.GetCache("player")
p := cache.Get(playerId)      // miss 自动回源
cache.Set(playerId, player)   // 更新缓存

持久化用例 —「先更内存，再落库」：

func (r *PlayerRepository) SavePlayer(p *playerdomain.Player) {
  cache, _ := r.cacheManager.GetCache("player")
  cache.Set(p.GetId(), p)
  r.inner.SavePlayerToDb(p)   // 异步落库（AsyncDBService）
}

每个表一个独立 Cache（默认 30min 过期 / 10s 清理）。定时脏数据落盘走 schedule（例：NewDefaultTaskScheduler）。

Service 注入（dig）

internal/bootstrap/services.go 用 go.uber.org/dig 做依赖注入。加一个 service：

  1. 1构造函数入参用 dig.In，返回值普通指针。
  2. 2registerServices 里 c.Provide(NewXxxService)；接口就用转函数 c.Provide(func(...) XxxInterface {...})。
  3. 3Services struct 加字段供 route 注入；实现了 ServiceModule.Init() 的会被自动调 init（用于订阅、缓存回源）。
type FriendServiceParams struct {
  dig.In
  PlayerRepo *playerrepo.PlayerRepository
  Cache      *cache.Manager
}
func NewFriendService(p FriendServiceParams) *FriendService { … }
// registerServices:
_ = c.Provide(friend.NewFriendService)

把上面的串起来，从零加一个 gacha 模块，6 个文件 + 3 处改动。参照 friend 模块既有结构。

文件清单

internal/domain/config/gacha.go          # 配置 PO

1 · 消息 protos/gacha.go

type ReqGachaDraw struct {
  _      struct{} `cmd_ref:"CmdGachaDrawReq"`
  Pool   int32 `json:"pool"`
  Times  int32 `json:"times"`
}
type ResGachaDraw struct {
  _       struct{} `cmd_ref:"CmdGachaDrawRes"`
  Code    int32  `json:"code"`
  ItemIds []int32 `json:"itemIds"`
}
// message.go:
CmdGachaDrawReq int32 = 4201
CmdGachaDrawRes int32 = 4251

2 · service gacha.go

type GachaService struct{ conf *container.GachaContainer }
type GachaServiceParams struct{ dig.In; Conf *container.GachaContainer }
func NewGachaService(p GachaServiceParams) *GachaService {
  return &GachaService{conf: p.Conf}
}
func (s *GachaService) Draw(pool, times int32) []int32 {
  ids := make([]int32, 0, times)
  for i := int32(0); i < times; i++ {
    ids = append(ids, s.conf.NextDrop(pool))
  }
  return ids
}

3 · route route/gacha.go

type GachaRoute struct{ service *gacha.GachaService }
func NewGachaRoute(service *gacha.GachaService) *GachaRoute { … }
func (r *GachaRoute) ReqGachaDraw(
  playerId string, index int32, msg *protos.ReqGachaDraw,
) *protos.ResGachaDraw {
  ids := r.service.Draw(msg.Pool, msg.Times)
  return &protos.ResGachaDraw{Code: 0, ItemIds: ids}
}

常见坑位

坑说明
改了协议没 go generatehandler 找不到 / 构建报错。协议、路由文件手工改；自动生成别动
message.go 里加注释解析会出错
消息没带 cmd_refprotocolgen 认不出来，register 里没有，路由注册不进去
Ask 嵌套同 actor / 互 Ask 死锁，用 Tell
并发改同一 entity没走 Actor / Dispatcher，靠你自己加锁
配置字段没 excel tag加载 ignoreUnknownFields=true 会静默读不到
